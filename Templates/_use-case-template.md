# Шаблон описания варианта использования

Единый шаблон (стиль А. Кокберна), применяемый ко всем вариантам использования платформы NovaMarket. Является рекомендованным прототипом для use case.

## Структура

### 1. Название
- Глагольная формулировка цели: «Оформить заказ», «Отследить статус заказа».
- Указывается ID варианта использования (UC-01, UC-02, …) и название.

### 2. Акторы
- Основной актор — инициатор, чья цель достигается.
- Второстепенные акторы — системы и люди, участвующие в сценарии (платёжная система, логистика, продавец).

### 3. Описание / Цель
Краткое описание того, чего хочет достичь основной актор (1–2 предложения).

### 4. Предусловия
Условия, которые должны выполняться до начала сценария (корзина не пуста, аккаунт авторизован и т. п.).

### 5. Триггер
Событие, запускающее вариант использования («Покупатель нажимает „Оформить заказ“»).

### 6. Основной сценарий
Нумерованный список шагов с чередованием «Актор → Система»:

1. Покупатель делает действие…
2. Система отвечает…
3. …

### 7. Расширения / альтернативные потоки
Номер элемента расширения соответствует номеру шага основного сценария, у которого он вызывает ветвление:

- 3a. Условие ветвления:
  - 3a-1. Действие…
  - 3a-2. Действие…

### 8. Постусловия
- Гарантия успеха: состояние системы после успешного завершения.
- Минимальная гарантия: состояние системы, если сценарий прервался (что остаётся верным при любом исходе).

### 9. Бизнес-правила
Бизнес-ограничения и данные, влияющие на сценарий (статусы, лимиты, требования к точности данных).

### 10. Примечания
Дополнительные соображения, бизнес-ценность, обоснования решений.
