# Текущая организационная структура OrchestrPay выглядит так: #

1. **Отдел «Платёжные сервисы»:** отвечает за разработку и развитие ключевых микросервисов платёжной платформы. Внутри отдела есть собственные команды, которые работают над отдельными доменами (например, обработка транзакций, возвраты, интеграции с внешними сервисами).

2. **Отдел «Финансы»:** взаимодействует с банками, платёжными шлюзами и системами бухгалтерского учёта. Отвечает за финансовую отчётность и сверку операций.

3. **Команда «Customer Support»:** обрабатывает обращения пользователей, связанные с платежами, сбоями и возвратами. Использует систему событий и интерфейсы для быстрой ручной обработки исключений.

4. **Команда «Безопасность»:** разрабатывает и внедряет antifraud-политики, анализирует угрозы, участвует в архитектурном контроле и проводит аудиты безопасности.

5. **Команда «DevOps/SRE»:** отвечает за стабильность, масштабируемость и автоматизацию инфраструктуры, мониторинг и логирование.

## На данный момент определены такие сервисы: ##

1. **Payment Service** — основной сервис обработки платежей.
2. **FraudCheck Service** — анализирует транзакции по внутренним правилам и через внешних провайдеров.
3. **Notification Service** — отправляет клиентам уведомления о статусах операций.

В процесс также вовлечены сервисы compliance-проверок и контроля ограничений, но их реализация выходит за рамки проектной работы.

## Какие технологии и системы используются: ##

1. **Camunda BPMN** — исполнение бизнес-процессов и реализация Saga-оркестрации с поддержкой компенсационных транзакций.
2. **Redis** — высокодоступное кеширование лимитов, фрод-меток, промежуточных статусов транзакций и результатов внешних проверок (например, AML/GeoRisk).
3. **PostgreSQL** — основное хранилище для транзакций, логов операций, пользовательских данных и настроек системы, которое также может использоваться для хранения состояний Saga.
4. **ArchUnit** — автоматическая проверка соблюдения архитектурных ограничений.
5. **Testcontainers** — лёгкое и воспроизводимое окружение для интеграционных и end-to-end тестов.
