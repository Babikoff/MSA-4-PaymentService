# Антифрод проверка платежа

**FraudCheck Service**  анализирует транзакции по внутренним правилам и через внешних провайдеров.

## Структура

### 1. Название

Проверка законности платежа.

### 2. Акторы

- **Основной:** Система автоматической проверки платежа.
- **Второстепенные:** Оператор, проверяющий платёж в ручном режиме.

### 3. Описание / Цель

Проверить платёж.

Использовать факт проверки во время будущих проверок:

1. Пропускать повторяющиеся платежи на аналогичную сумму в течении определённого времени при соблюдении пауз между платежами.

2. Агрерированно анализировать повторяющиеся платежи (на предмет разбиения на мелкие платежи и т.п.).

### 4. Предусловия

- Система запущена.

### 5. Триггер

В систему поступает платёж на проверку.

### 6. Основной сценарий

1. В систему поступает платёж на проверку.
2. В качестве ответа система FraudCheck Service может возвращать три типа ответа:

  - 2.1. **Разрешение** - транзакция может быть проведена.
  - 2-2. **Запрет** - транзакция отклоняется.
  - 2-3. **Ручная проверка** - транзакция направляется на рассмотрение оператору, который должен принять решение в течение 20 минут. По результатам ручной проверки сервис возвращает одно из окончательных решений:
    - 2-3-1. **Разрешение**.
    - 2-3-2. **Запрет**.
  На время ручной проверки транзакция должна находиться в состоянии ожидания. Если сервисы проверок не возвращают ответ в установленное время, то предусмотрен cut-off-time. По его истечении транзакция по умолчанию считается разрешённой и проводится.

- **Минимальная гарантия:** проверка пройдена.
